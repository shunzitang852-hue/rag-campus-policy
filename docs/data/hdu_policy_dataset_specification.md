# 杭州电子科技大学政策数据集采集规范

## 一、研究对象

本数据集的研究对象为杭州电子科技大学。

本规范服务于本科毕业论文《基于RAG技术的高校政策知识问答系统构建与检索策略优化研究》，用于指导第一版高校政策知识问答系统的数据采集、元数据登记和人工核验。

## 二、数据适用群体

第一阶段只收集与普通全日制本科生直接相关的校级政策文件。

暂不纳入研究生、国际学生、继续教育学生、教职工、科研人员或单个学院内部管理场景的专门文件。

## 三、第一版数据规模

第一版政策文档目标规模为 20 至 30 份。

该规模用于完成数据采集流程验证、元数据管理、后续解析流程验证和初步检索实验准备，不追求一次性覆盖全部校级政策。

## 四、政策类别及代码

| 类别代码 | 类别名称 | 说明 |
| --- | --- | --- |
| STUDENT_STATUS | 学籍管理 | 学籍注册、异动、休学、复学、转专业等本科生学籍相关政策。 |
| TEACHING | 教学与课程 | 培养方案、课程修读、教学运行、学分认定等政策。 |
| EXAM | 考试管理 | 考试组织、成绩管理、补考、缓考、考试纪律等政策。 |
| GRADUATION | 毕业与学位 | 毕业资格、学位授予、毕业审核等政策。 |
| SCHOLARSHIP | 奖助与评优 | 奖学金、助学金、评奖评优、困难认定等政策。 |
| DISCIPLINE | 纪律处分 | 学生违纪处理、处分、申诉等政策。 |
| DORMITORY | 宿舍管理 | 学生住宿、宿舍纪律、安全和日常管理等政策。 |
| EMPLOYMENT | 就业与实习 | 就业管理、实习实践、就业服务等本科生相关政策。 |
| CAMPUS_SERVICE | 校园事务 | 校园卡、图书馆、网络、公共服务等学生事务政策。 |

`HANDBOOK` 目录用于存放学生手册等综合性文件，但 `HANDBOOK` 不作为最终单一问答类别。对学生手册中的条目进行后续利用时，应根据具体内容映射到上述九类政策范围。

## 五、数据纳入标准

纳入数据应同时满足以下条件：

1. 文件来源为杭州电子科技大学官方域名、校内职能部门官方网站或学校正式发布平台。
2. 文件内容与普通全日制本科生直接相关。
3. 文件属于当前九类政策范围，或为可拆分映射到九类政策的综合性学生手册。
4. 文件标题、发布部门、来源页面或附件信息可以被人工核验。
5. 能够记录原始发布页、下载地址、下载日期和文件名。
6. 文件未被明确标注为废止；若存在新旧版本，应优先保留较新且仍适用的版本。
7. 文件格式适合后续解析和检索实验，例如 PDF、DOCX、DOC、HTML 转存文本或学校正式发布的附件。

## 六、数据排除标准

以下内容暂不纳入第一版数据集：

1. 研究生政策。
2. 国际学生政策。
3. 继续教育政策。
4. 招生宣传材料。
5. 新闻报道。
6. 校园活动通知。
7. 科研、人事、财务和教职工管理制度。
8. 只适用于单个学院的内部通知。
9. 搜索引擎摘要、非官方转载、个人整理文档或无法确认来源的材料。
10. 与普通全日制本科生没有直接关系的校级管理文件。

## 七、官方来源优先级

数据采集时按以下优先级选择来源：

1. 杭州电子科技大学学校官网正式发布页面。
2. 杭州电子科技大学教务处、学生处、研究生院以外的本科生相关职能部门官方网站。
3. 杭州电子科技大学官方信息公开、规章制度或学生手册发布页面。
4. 学校统一认证、统一门户或校内正式系统中可核验的公开文件。

当多个来源同时存在时，应优先选择发布部门更明确、附件更完整、版本更新且页面信息更可核验的来源。

## 八、文件有效性核验规则

每份文件在进入正式数据集前必须人工核验：

1. 核验来源页面是否属于杭州电子科技大学官方来源。
2. 核验发布部门是否明确。
3. 核验标题、文号、发布日期、生效日期和适用对象。
4. 检查是否存在废止、修订、替代或新版发布说明。
5. 检查文件是否适用于普通全日制本科生。
6. 检查网页正文标题与下载附件标题是否一致。
7. 记录下载日期、原始发布页、下载地址和 SHA-256 哈希。
8. 禁止根据网页更新时间直接推断政策生效日期。

如果发布日期、生效日期或有效性无法确认，应在元数据中标记为 `pending_verification`，并在 `verification_notes` 中说明原因。

## 九、重复文件和新旧版本处理规则

1. 同一政策存在多个完全相同附件时，应通过文件名、文件大小和 SHA-256 哈希识别重复项。
2. 同一政策存在多个版本时，应保留版本关系记录，不得简单覆盖旧文件。
3. 如果新版明确废止或替代旧版，应在旧版的 `validity_status` 中标记为 `superseded` 或 `repealed`。
4. 如果无法确认新旧关系，应暂时保留候选记录，并标记为 `pending_verification`。
5. 文件重命名只改变本地保存名，不得改变原始文件内容。

## 十、文件命名规范

本项目采用以下命名格式：

```text
HDU_类别代码_发布日期_文件简称_版本号.扩展名
```

示例：

```text
HDU_GRADUATION_20221202_本科毕业生学士学位授予细则_v1.pdf
HDU_STUDENT_STATUS_UNKNOWN_本科学生学籍管理规定_v1.pdf
HDU_HANDBOOK_20170901_学生手册_v1.pdf
```

命名要求：

1. `类别代码` 使用本规范定义的类别代码。
2. `发布日期` 使用 `YYYYMMDD` 格式。
3. 未确认发布日期时必须使用 `UNKNOWN`，不得猜测日期。
4. `文件简称` 应尽量保留政策核心名称，避免使用过长标题。
5. `版本号` 从 `v1` 开始；同一文件存在人工核验后的新版本时递增。
6. 扩展名应与实际文件格式一致。

## 十一、元数据字段说明

`policy_metadata_template.csv` 字段说明如下：

| 字段 | 说明 |
| --- | --- |
| document_id | 本地文档唯一编号。 |
| title | 政策文件标题。 |
| university | 学校名称，后续固定填写“杭州电子科技大学”。 |
| department | 发布部门。 |
| category | 政策类别代码。 |
| document_number | 文号。 |
| publish_date | 发布日期。 |
| effective_date | 生效日期。 |
| expiry_date | 失效日期。 |
| validity_status | 有效性状态。允许值：`valid`、`likely_valid`、`repealed`、`superseded`、`pending_verification`。 |
| applicable_group | 适用群体。 |
| source_page_url | 原始发布页 URL。 |
| download_url | 附件下载 URL。 |
| file_name | 本地文件名。 |
| file_type | 文件类型。 |
| page_count | 页数。 |
| has_text_layer | 是否有文本层。允许值：`true`、`false`、`unknown`。 |
| content_hash | 文件 SHA-256 哈希。 |
| retrieved_at | 下载或采集日期时间。 |
| replacement_document | 替代文件或新版文件说明。 |
| verification_notes | 人工核验备注。 |

`policy_collection_candidates.csv` 只用于候选政策线索管理，不代表文件已经通过核验，也不得作为正式元数据直接使用。

## 十二、人工核验责任说明

Codex 可以辅助创建目录、模板、核验清单、脚本和后续解析流程，但不能替代项目负责人进行事实判断。

以下事项必须由项目负责人亲自核验：

1. 政策文件是否来自官方来源。
2. 政策文件是否真实有效。
3. 政策文件是否已经废止、修订或被替代。
4. 政策文件是否适用于普通全日制本科生。
5. 元数据中的发布日期、生效日期、文号和发布部门是否准确。
6. 文件类别、适用范围和版本关系是否合理。

## 十三、禁止事项

1. 禁止根据网页更新时间直接推断政策生效日期。
2. 禁止将新闻稿、搜索引擎摘要和非官方转载作为正式政策正文。
3. 禁止填入未经人工核验的正式元数据。
4. 禁止为满足数量目标而收集与研究范围无关的文件。
5. 禁止在没有来源页面和下载记录的情况下直接使用本地文件作为正式数据。
