# 杭州电子科技大学信息工程学院政策数据集采集规范

## 一、研究对象

本数据集的研究对象为杭州电子科技大学信息工程学院。

简称：杭电信工

机构代码：`hdu_ies`

本规范服务于本科毕业论文《基于RAG技术的高校政策知识问答系统构建与检索策略优化研究》，用于指导第一版高校政策知识问答系统的数据采集、元数据登记和人工核验。

本研究选取杭州电子科技大学信息工程学院的学生管理制度及相关高校政策文件作为主要案例语料，构建高校政策知识库，并对Dense、BM25和Hybrid等检索策略进行对比研究。

## 二、数据适用群体

第一阶段重点收集与杭州电子科技大学信息工程学院普通全日制本科生直接相关的制度和政策文件。

国家及教育部层面的政策文件只作为上位政策和补充语料。后续若加入杭州电子科技大学本部或其他高校政策，必须作为独立机构语料保存，不得与 `hdu_ies` 混用。

## 三、主要语料范围

主要语料包括：

1. 学生手册。
2. 学籍管理制度。
3. 学位授予制度。
4. 奖助学金制度。
5. 考试纪律制度。
6. 毕业设计与论文管理制度。
7. 学生申诉与处分制度。
8. 创新创业和学科竞赛制度。

| 类别代码 | 类别名称 | 说明 |
| --- | --- | --- |

## 五、数据纳入标准

纳入数据应同时满足以下条件：

1. 文件来源可核验，且发布主体或适用范围能够确认与杭州电子科技大学信息工程学院相关。
2. 文件内容与杭州电子科技大学信息工程学院普通全日制本科生直接相关。
3. 文件属于当前政策类别范围，或为可拆分映射到多个类别的综合性学生手册。
4. 文件标题、发布主体、来源页面、附件信息或纸质版本信息可以被人工核验。
5. 能够记录原始来源、下载或取得日期、本地文件名和 SHA-256 哈希。
6. 文件未被明确标注为废止；若存在新旧版本，应优先保留较新且仍适用的版本。
7. 文件格式适合后续解析和检索实验，例如 PDF、DOCX、DOC、TXT 或经核验的网页正文。

## 六、数据排除标准

以下内容暂不纳入第一版正式数据集：

1. 杭州电子科技大学本部政策，除非明确作为上位政策或补充语料单独标记。
2. 其他高校政策。
3. 研究生、国际学生或继续教育学生政策。
4. 招生宣传材料。
5. 新闻报道。
6. 校园活动通知。
7. 科研、人事、财务和教职工管理制度。
8. 无法确认是否适用于杭州电子科技大学信息工程学院学生的材料。
9. 搜索引擎摘要、非官方转载、个人整理文档或无法确认来源的材料。

## 七、官方来源优先级

数据采集时按以下优先级选择来源：

1. 杭州电子科技大学信息工程学院官方网站或公开发布平台。
2. 杭州电子科技大学信息工程学院学生手册、规章制度汇编或可核验纸质版本。
3. 杭州电子科技大学本部、国家或教育部发布的上位政策文件，仅作为补充语料并独立标记。
4. 其他可核验来源，但必须记录 `verification_status` 和 `verification_note`。

当多个来源同时存在时，应优先选择发布主体更明确、版本更新、适用范围更清楚且页面信息更可核验的来源。

## 八、文件有效性核验规则

每份文件进入正式数据集前必须人工核验：

1. 核验来源页面或纸质版本是否真实可追溯。
2. 核验发布机构是否为杭州电子科技大学信息工程学院，或是否属于上位补充政策。
3. 核验标题、文号、发布日期、生效日期和适用对象。
4. 检查是否存在废止、修订、替代或新版发布说明。
5. 检查文件是否适用于杭州电子科技大学信息工程学院普通全日制本科生。
6. 检查网页正文标题与下载附件标题是否一致。
7. 记录来源、下载或取得日期、本地文件名和 SHA-256 哈希。
8. 禁止根据网页更新时间直接推断政策生效日期。

如果发布日期、生效日期、文号或有效性无法确认，应在元数据中留空，并在 `verification_note` 中说明原因。

## 九、重复文件和新旧版本处理规则

1. 同一政策存在多个完全相同附件时，应通过文件名、文件大小和 SHA-256 哈希识别重复项。
2. 同一政策存在多个版本时，应保留版本关系记录，不得简单覆盖旧文件。
3. 如果新版明确废止或替代旧版，应在旧版的 `validity_status` 中标记为 `superseded` 或 `invalid`。
4. 如果无法确认新旧关系，应暂时保留候选记录，并标记为 `pending_verification`。
5. 文件重命名只改变本地保存名，不得改变原始文件内容。

## 十、文件命名规范

本项目采用以下命名格式：

```text
HDU_IES_类别代码_发布日期_文件简称_版本号.扩展名
```

示例：

```text
HDU_IES_HANDBOOK_UNKNOWN_学生手册_v1.pdf
HDU_IES_SCHOLARSHIP_UNKNOWN_国家奖学金评审办法_v1.pdf
HDU_IES_GRADUATION_UNKNOWN_毕业设计论文管理办法_v1.pdf
```

命名要求：

1. `类别代码` 使用本规范定义的类别代码。
2. `发布日期` 使用 `YYYYMMDD` 格式。
3. 未确认发布日期时必须使用 `UNKNOWN`，不得猜测日期。
4. `文件简称` 应尽量保留政策核心名称，避免使用过长标题。
5. `版本号` 从 `v1` 开始；同一文件存在人工核验后的新版本时递增。
6. 扩展名应与实际文件格式一致。

## 十一、元数据字段说明

`policy_metadata_template.json` 字段说明如下：

| 字段 | 说明 |
| --- | --- |
| document_id | 本地文档唯一编号。 |
| institution_id | 固定为 `hdu_ies`。 |
| institution_name | 固定为“杭州电子科技大学信息工程学院”。 |
| institution_short_name | 固定为“杭电信工”。 |
| document_title | 政策文件标题。 |
| issuer | 发布机构，必须根据文件原文填写，不能自动假设。 |
| document_number | 文号；无法确认时留空。 |
| document_type | 文件类型，例如学生手册、管理办法、实施细则等。 |
| document_level | 文件层级，例如学院制度、学校上位政策、国家上位政策等。 |
| publish_date | 发布日期；无法确认时留空。 |
| effective_date | 生效日期；无法确认时留空。 |
| validity_status | 有效性状态。 |
| applicable_scope | 适用范围，例如杭州电子科技大学信息工程学院普通全日制本科生。 |
| source_url | 正式来源网址；没有正式来源网址时留空，不得伪造。 |
| local_source_path | 本地原始文件路径。 |
| retrieved_date | 下载或取得日期。 |
| verification_status | 只允许 `verified`、`partially_verified`、`pending_verification`、`invalid`。 |
| verification_note | 核验说明。 |
| page_start | 起始页码；未知时为 `null`。 |
| page_end | 结束页码；未知时为 `null`。 |
| content_hash | 文件 SHA-256 哈希。 |

## 十二、人工核验责任说明

Codex 可以辅助创建目录、模板、核验清单、脚本和后续解析流程，但不能替代项目负责人进行事实判断。

以下事项必须由项目负责人亲自核验：

1. 政策文件是否来自可追溯来源。
2. 政策发布主体是否为杭州电子科技大学信息工程学院或明确的上位政策发布机构。
3. 政策文件是否真实有效。
4. 政策文件是否已经废止、修订或被替代。
5. 政策文件是否适用于杭州电子科技大学信息工程学院普通全日制本科生。
6. 元数据中的发布日期、生效日期、文号和发布机构是否准确。
7. 文件类别、适用范围和版本关系是否合理。

## 十三、禁止事项

1. 禁止根据网页更新时间直接推断政策生效日期。
2. 禁止将新闻稿、搜索引擎摘要和非官方转载作为正式政策正文。
3. 禁止填入未经人工核验的正式元数据。
4. 禁止为满足数量目标而收集与研究范围无关的文件。
5. 禁止在没有来源页面、纸质版本说明或取得记录的情况下直接使用本地文件作为正式数据。
6. 禁止把杭州电子科技大学本部政策直接标记为杭州电子科技大学信息工程学院政策。
