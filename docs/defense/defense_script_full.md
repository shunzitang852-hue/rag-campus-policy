# 开题答辩完整逐字稿（15 页，约 5–7 分钟）

论文题目：《基于RAG技术的高校政策知识问答系统构建与检索策略优化研究》

建议时长：约 6 分钟。第 6–10 页可根据老师兴趣展开或快速带过。

## 第1页｜封面

各位老师好，我的论文题目是《基于RAG技术的高校政策知识问答系统构建与检索策略优化研究》。本次汇报主要包括研究背景、研究设计、系统与代码实现、阶段性实验结果、典型案例和后续计划。

## 第2页｜研究背景与核心问题

高校政策文件通常数量多、篇幅长，而且同一事项可能分散在不同条款。用户更习惯自然语言提问，但传统关键词检索依赖词面匹配，找到文件后仍需人工筛选。若直接让大语言模型回答，又会面临证据不足、政策事实被混用和引用不可追溯的问题。因此本研究采用 RAG：先从本地政策库检索可信证据，再约束模型基于证据生成回答。

## 第3页｜研究目标与主要研究内容

研究目标不是只做一个聊天界面，而是构建面向高校政策场景的 RAG 问答系统，并系统分析知识切分与检索策略对结果的影响。具体工作包括政策清洗与结构化、固定长度、按条款和结构感知三种切分方式，BM25、Dense 和 Hybrid 三类检索，以及抽取式和生成式回答的自动评价与人工复核。核心研究变量是 Chunk Strategy 与 Retrieval Strategy 的组合。

## 第4页｜数据与实验设计

当前数据来自杭州电子科技大学信息工程学院学生政策和学生手册，共构建四十道测试题。三种切分分别产生二百四十四、三百五十八和三百五十八个 Chunk。检索阶段使用 Recall@K、MRR@K、Gold policy hit 和 relevant chunk hit；回答阶段使用关键词覆盖、证据覆盖、Automatic Good 或 Needs Review，并对典型样本进行人工评价。每次正式实验还保存参数、数据 SHA-256 清单和逐题结果。

## 第5页｜系统架构与代码组织

项目按照 preprocessing、chunking、retrieval、rag 和 experiments 分层。完整链路从政策原文开始，经过清洗、政策拆分和结构解析，生成三套知识切分，再完成词面、语义或混合检索。Top-5 结果被组织为长度受控的 Context，进入版本化 Prompt 和 LLM Provider；Citation 独立读取检索元数据生成。最后，实验管理模块把配置、逐题结果和汇总指标登记到统一总账，并导出论文表格。

## 第6页｜核心实现一：政策处理与知识切分

这一页展示真实代码。预处理模块依次负责文本清洗、政策拆分和章节条款解析。`generate_chunks` 是统一切分入口，根据配置分派 `fixed_length`、`article_based` 和 `structure_aware` 三种策略。三套正式输出已经全部生成，用于后续可控比较。

## 第7页｜核心实现二：BM25 与 Dense Retrieval

BM25 使用不依赖第三方分词器的中文字符与相邻二元组合，保证实验可复现，并按 BM25 公式完成词面相关性排序。Dense 使用真实中文向量模型编码问题，再与预计算的 Chunk 向量计算余弦相似度，并采用稳定排序处理同分结果。两者分别构成 lexical 与 semantic 基线。

## 第8页｜核心实现三：Hybrid 检索策略

Hybrid 先在每一道问题内部对 Dense 和 BM25 分数分别做 min-max 归一化，再按零点五和零点五进行加权融合。正式配置的候选池为五十，最终返回 Top-5。项目也实现了 RRF，便于比较，但进入生成式 RAG 的固定方案是 Weighted Hybrid。

## 第9页｜核心实现四：生成式 RAG Pipeline

`answer_query` 将检索、Context 构建、生成和引用串联起来。系统先获得检索结果，再根据 Top-K 和最大字符数构建 Context。当回答模式为 LLM 时，只有在 Context 存在时才建立 Provider 并生成回答；随后程序根据相同 Context 构建 Citation，最终统一返回答案、证据和检索信息。

## 第10页｜核心实现五：Prompt 与可信引用

Prompt 有明确版本，并要求只能依据用户消息中的政策上下文作答；证据不足时要明确说明无法确认；不得编造政策名称、条款号或引用。Provider 负责构造兼容接口的请求载荷。Citation Builder 则读取政策标题、Chunk ID、分数和摘录，因此答案由模型生成，而正式引用由程序控制，降低虚构引用风险。

## 第11页｜实验管理与代码可靠性

`ExperimentRecorder` 在运行开始时记录配置、运行环境、输入数据清单和 Git 状态，并保存 metrics、逐题 JSONL、汇总 CSV 与日志。`Registry` 建立统一实验总账，`Thesis Export` 只从已登记的持久化结果生成论文表格。规范化 RAG workflow 完成时全量测试为 `226 passed`，生成式正式实验为四十题全部成功。这说明当前不仅有结果，也具备可追踪和可复现的工程基础。

## 第12页｜检索策略实验与优化结果

在四十题、固定长度切分和 Top-5 的统一条件下，BM25 的 Recall@5 为零点九五，MRR@5 为零点八七零八；Dense 分别为一点零和零点九八三三；Hybrid 两项均为一点零。综合切分与检索组合实验，后续 RAG 固定采用 Weighted Hybrid、固定长度切分和 Top-5，Dense 与 BM25 权重各零点五，候选池五十，归一化方式为 per-query min-max。这里报告的是检索指标，不表述为问答准确率。

## 第13页｜生成式 RAG 阶段性实验结果

三组抽取式基线的关键词覆盖分别为零点五四三三、零点五七三三和零点五四六七，证据覆盖分别为零点七六五八、零点七九二九和零点八七二一。生成式 RAG 的关键词覆盖达到零点七零三三，证据覆盖达到零点八九七九，四十题全部生成成功，并有二十九题被自动标为 Good。需要强调，Automatic Good 是自动辅助信号，不等于人工准确率，不能外推为完整四十题人工评价结论。

## 第14页｜典型案例与评价分析

Q018 是成功案例。问题涉及转学条件、办理主体和时间要求，生成式回答能够把分散信息按主体重新组织，同时保留关键条件。Q032 用于说明评价限制：题目要求第一条中的责任或义务，但 Gold policy 第一条实际只说明制定目的和依据。模型据此回答无法从材料确认，自动指标却偏低。因此该题应归类为 automatic evaluation limitation 或 QA alignment issue，而不是简单标记为 LLM failure。它说明自动指标必须结合政策原文和人工复核解释。
